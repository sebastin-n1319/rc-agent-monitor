# Tech Onboarding Process and Workflow

Adit’s tech onboarding consists of distinct phases that gently guide the client into using our full platform and integrating its functions into the daily work flow of their practice. These phases are:  
Phase 0: Account Setup  
Phase 1: Core Platform  
Phase 2: Adoption  
Phase 3: Go Live

## How to Use This Document {#how-to-use-this-document}

This document outlines the entire tech onboarding process and the onboarding client lifecycle. It includes instructions on how to do every part of tech onboarding, including what fields to update in CRM and what parts of the process will require assistance from other teams.

Any steps of the onboarding process not covered directly in this document are calls or meetings that require their own separate process documentation; these are linked throughout the document where needed for easy reference as well as in the Appendix.

Use the Table of Contents (below) or the Outline (in the left navigation panel) to jump to a specific section.

## Phase 0: Account Setup {#phase-0:-account-setup}

Account setup is almost entirely automated. It begins when a client signs their Agreement with Adit, which automatically creates the Tech OB record (also known as the TO-record)  in CRM. This is still technically part of the Sales process; Onboarding does not begin until later.

### Stage: Pending Server Install {#stage:-pending-server-install}

The first stage for the TO-record is Pending Server Install. During this stage, the AE will guide the client through the account setup process, which includes installing the server sync app (Pozative.exe). This entire setup process occurs within the Adit platform’s “Get Started” checklist. The items set up during this stage can include:

* Done by the client:  
  * Add their business hours  
  * Add their front desk / receptionist’s email address  
  * Create users  
  * Put a credit card on file for overage charges  
  * Set up an outbound phone number (will be a temporary number if they are porting)  
  * Provide porting information (if applicable)  
  * Provide info about their IT provider (if they have one)  
  * Install the server sync app (Pozative) on their server computer  
  * Connect their Google Business page (optional)  
  * Upload their practice’s logo (optional)  
  * Download the Adit mobile and desktop apps (optional)  
* Done by Adit:  
  * Order phones as selected by the client on their agreement (automatic)  
  * Add tracking number and expected delivery date in CRM (automatic)

The specific items included in an individual client’s Get Started checklist will vary based on their package and their intent to use Adit Voice or not.

There are three requirements for a client move from the Account Setup phase into Onboarding:

1. All required Get Started steps complete.  
2. Phones ordered and shipped (if applicable).  
   1. Tracking Number / Expected Delivery Date for phones updated in CRM, or  
   2. The client did not order phones.

Once all of these requirements have been met, the Deal stage will move to Onboarding and the Tech OB record stage will automatically update to **Pending Phone Install**. If the client will not be using Adit Voice, the stage will move to **Pending Kickoff**.

## Phase 1: Core Platform {#phase-1:-core-platform}

### Stage: Pending Phone Install / Pending Kickoff {#stage:-pending-phone-install-/-pending-kickoff}

This is where Onboarding officially begins. The OB will see the client listed in their CRM dashboard, in the section for “Schedule/Reschedule Kickoff”, as well as receive an email notification. This is the OB’s signal to reach out to the client to introduce themselves, talk about the onboarding process and schedule their first three meetings.

#### Client Research {#client-research}

Before the OB calls the client for the first time, they will need to do a small amount of research in CRM:

* Check the Deal to see what Package they have signed up for and if they will be using Adit Voice, Adit Pay, Analytics, RCM or Call Intelligence. This will tell the OB what modules are included in their package and will need to be set up during their onboarding.  
* Check the AE’s notes about the client’s current setup, their needs and goals, pain points, and other information.  
* Check the Account and Deal to see if the AE included any additional notes as to the client’s specific needs, who to contact, when to contact them, or anything else the OB may need to know about the client.  
* Check the TO-record and ensure the information in the following sections has pulled over correctly; if it has not, update it.  
  * Deal Details (pulls over from Deal in CRM)  
  * Module Opt In (depends on agreement and client preferences)  
  * Account Set Up (pulls in from Adit App)  
  * Server Install (is Server Install Complete checked)

**\*Note: If the client has opted out of Adit Voice**, the stage of their TO-record will be **Pending Kickoff**. Please make sure to omit any parts of the onboarding process specific to phones and eFax. This includes (but is not limited to) whitelisting, phone installation, configuring call flow, and training on these features.

#### Intro Call {#intro-call}

OB calls the client to introduce themselves and start building rapport. This call should only take about 15 minutes. Here are some things the OB must mention:

* That you will be their main point of contact during their onboarding with Adit, and that you are excited to work with them\!  
* Your direct contact info (direct phone number for calls and texts, [support at adit.com](mailto:support at adit.com) for emails).  
* Confirm the main point of contact (POC) at the office for their onboarding.  
  * Make sure you have that person’s correct name, phone number, and email.  
  * Confirm and/or Update this info in CRM (on the Account, Deal, and TO-record) after the call.  
* Let them know you are calling today to schedule their three “big” onboarding calls.  
* Briefly explain the Kickoff Call / Phone Install:  
  * Includes three parts:  
    * Overview of the onboarding process,  
    * Discussion about their practice needs and goals, and  
    * Installing their new phones (if applicable).  
  * If using Adit Voice:  
    * Be prepared for this call to take at least two hours, possibly up to four depending on how many phones need to be installed. Make sure the client is aware of and agrees to this time commitment.  
      * Kickoff portion: 30-60 minutes  
      * Installing phones: about 30 minutes per phone for the first 3, plus about 10 minutes for each additional phone.  
      * POC should be involved in the Kickoff portions of the call but does not need to handle the phone installation themselves; they can delegate the phone setup to their IT person or to another member of their team who can more easily commit to the required block of time.  
    * Schedule the Kickoff w/ Phone Install:  
      * Must be 5-6 days from today, should be the day before the Config Call.  
      * Must be after the Phones Expected Delivery Date.  
      * Must be able to meet for 2-3 consecutive days (for Kickoff, Config, and Staff Training).  
    * Start preparing for a smooth phone installation. Refer to VoIP vs Traditional Phone Service for more information and questions to ask the client.  
  * If no Voice:  
    * Call will take around 30-45 minutes.  
    * Schedule within the next 3 days.  
* Explain and schedule the Config Call:  
  * About 60 minutes.  
  * Allows the client to review and confirm the configuration of their platform.  
  * Teaches the Office Manager and/or practice admins how to access and update settings if needed in the future.  
  * Schedule the Config Call:  
    * Should be the day after their Kickoff Call (no more than 2 days after).  
    * Must be at least 7 days from today.  
* Explain and schedule the Staff Training:  
  * About 1 hour, but can schedule for longer if they have a large team (more than 7).  
  * Covers the core platform features that the staff will use on a daily or weekly basis.  
  * Invite everyone on their team who will use any part of the Adit platform, including phones.  
  * The training will be recorded. Anyone who cannot make the scheduled time can watch the recording at their earliest convenience.  
  * Schedule the Staff Training:  
    * Should be the day after the Config Call.  
    * They will be turning on their Adit features during Config, so we want to make sure the staff is trained as soon as possible afterwards.  
* If the client has signed up for any of the following, a separate stand alone training session should be scheduled as well. Ex. Analytics, Pay, RCM or Call Intelligence

Update the **Kickoff Call Sched Date**, **Config Call Sched Date**, and **Staff** **Training Sched Date** fields in the TO-record in CRM with the agreed-upon date for each call. Update the contact info for your POC in the TO-record, Deal, and Account in CRM (if needed).

#### Email Phone Info {#email-phone-info}

When the client’s phones are delivered, you will see an update in your CRM dashboard letting you know that you need to email the client. In Desk, use the Phone Info template to send an email to the client. Update any placeholder text with the appropriate client information. Also in Desk, use the Whitelisting template to send a second email to the client’s IT contact and cc your POC. Update the **Whitelisting Email** field to **Sent** in the TO-record when both emails are sent.

The first email will help the client prepare for a successful phone installation by showing them in advance how to plug in the physical phones. The Whitelisting email provides important information about required whitelisting. Whitelisting is only required for about 10% of clients, but it’s a good idea to have their IT check their network configuration before the Kickoff Call to ensure everything is in place for our phones to work as soon as they are plugged in.

The OB will continue to follow up daily with the client and/or their IT until they confirm that whitelisting is done. Once you have received that confirmation, update the **Acknowledged by IT / Practice Manager** field in the TO-record.

#### Confirm Kickoff Call & Phone Info {#confirm-kickoff-call-&-phone-info}

One business day before the Kickoff Call, call the client to confirm the date and time of their Kickoff Call.

If they are using Adit Voice, remind them that their phones will also be installed during this call, so their IT person (if they have one) needs to be available as well. Confirm they received the email regarding phone setup and whitelisting. If they did not receive the email, confirm the email address and resend it. Ask the client to forward that email to their IT, if they have one, and to cc us on it so that our team can reach their IT in case any issues arise.

Update the **Kickoff Confirmed** field in the TO-record once you have confirmed the Kickoff call will proceed as scheduled.

#### Kickoff Call {#kickoff-call}

The Kickoff Call should occur within a few days of the client’s phones being delivered. For an in-depth look at the process and expectations before, during, and after this call, please see our Kickoff Call Process document.

The purpose of the Kickoff is to introduce the client to Adit and our Onboarding experience and set the client’s expectations for the rest of the onboarding process. You will also guide the client through installing their phones (if applicable) and give them a complete training on how to use them.

Once both the Kickoff Call and the Phone Install (if applicable) are completed successfully, click the **Phone Installed, Pending Config** transition on the TO-record

#### Phone Install Failed {#phone-install-failed}

If the phone installation was not successful, speak with the VoIP team, providing all relevant information to help get the issue resolved. The Onboarding cannot move forward until the phone install has been completed successfully.

### Stage: Pending Config {#stage:-pending-config}

During this stage, you will configure the Core platform for your client based on the information you have about them and the conversation you had during the Kickoff Call. This is only a preliminary configuration; you will update and confirm the settings once you have the client on the phone.

Remember that we are only concerned with the Core Platform at this phase of onboarding; you will only configure Engage, Pozative, Patient Forms, and eFax at this time. If your client plans on using Online Scheduling and knows how they want to set it up, you can include it as part of the Core Platform. If they are not sure about using OS yet, save that conversation for the Adoption phase so that you can spend as much time on it as needed.

#### Config Call {#config-call}

You will then have the Config Call with the client, during which you will:

1. Show the client what you have set up for them.  
2. Walk them through what each of the settings do and why you chose the configuration you did for their specific needs.  
3. Encourage the client to discuss these decisions with you, and  
4. Make any necessary changes to ensure the final configuration is correct and will meet their needs and goals.  
5. Turn on all automated messages and reminders.

For an in-depth look at the process and expectations before, during, and after this call, please see our Configuration Call Processdocument.

Once the Config Call is complete and the client is happy with the configuration you’ve set up, click the **Config Complete** transition on the TO-record.

### Stage: Pending Core Training {#stage:-pending-core-training}

During this stage, you will train the staff at the practice \- anyone who will be using the Adit platform or communicating with patients should be included in this training session, which should last around 60 minutes.

Since you turned on all of their automated messages and reminders in the Config Call, it is generally best to do the Staff Training as soon as possible after the Config.

#### Staff Training {#staff-training}

The goal of this training is to teach the staff how to use the Adit platform in their day-to-day work. Remember that you are only training on the Core platform. For a detailed list of what to cover before, during, and after this call, please refer to Staff Training Process.

You should not cover any settings or preferences in the staff training; 90% of staff will never change their settings and showing them how is just overloading them with more information than they need.

In order for the **Training Complete** transition to be available, two requirements must be met:

* The **Staff Training Complete** field must be updated to YES, and  
* The client’s Adoption Score must meet a threshold of 30 points (without Voice) or 60 points (with Voice). If they haven’t reached this threshold, they are not using the core features that you set up and enabled; follow up with the client to find out why and how you can help get them engaged with the platform.

## Phase 2: Adoption {#phase-2:-adoption}

### Stage: Pending Adoption {#stage:-pending-adoption}

The Adoption stage is where we will handle the configuration, training, and adoption of the rest of the Adit App. This will likely be the longest phase of the onboarding process. Onboarding Specialists will continue to follow up with your clients, run interference for any issues or bugs, and encourage them to use various pieces of the platform.

#### Additional Training {#additional-training}

If the client will be using Call Intelligence, this is when they will schedule their training, be sure to schedule the training session with the client for 60 minutes. If the client is not yet sure, schedule a demo call for the Upgrade team to pitch the platform to the client. Once their Call Intelligence training is completed, update the **Call Intelligence Onboarding** section of the TO-record. If the client will not be using Call Intelligence, make sure the feature is opted out in the TO-record.

If the client has Practice Analytics included in their package, this is when they will schedule their training with the PA team. To schedule this, have the client go into the Practice Analytics module and click the Schedule Training button near the top right of the page. Once this training session is scheduled, update the **PA Training** field to **Scheduled**. If the client decides they do not want to use Practice Analytics, you should involve their AE to ensure they were sold on the correct package. If necessary, they can be downgraded to a tech bundle.

If the client will be using Adit Pay, be sure to set them up for the Pay Configuration meeting with the Pay team. Note: when scheduling this call, be sure to check the availability on the Adit Pay Training calendar for proper availability, use this link for scheduling: [Adit Pay & Terminal Set Up](https://calendar.google.com/calendar/u/0/appointments/schedules/AcZssZ2hFxUOn0ZPh41LlZEvZF5hT26AfWXMK2Nm1jOpLGNGtVKQ2Ag7NYK0saSVnD9l4JHHV7Xq5Ir_)  If the client is not yet sure, schedule a call for the Pay team to pitch their platform to the client. Once their Adit Pay Configuration is scheduled, update the **Adit Pay Training** field to **Scheduled**. If the client will not be using Adit Pay, make sure the feature is opted out in the TO-record.

If the client has signed up for RCM, this is when they will schedule their training with the RCM team. To schedule this, have the client go into the RCM module and click the Schedule Training button near the top right of the page. Be sure to walk the client through the **Get Started** steps in the module and ensure the set up is completed prior to their scheduled training with the RCM team. If the client is not yet sure, schedule a demo call for the Upgrade team to pitch the platform to the client. Once their RCM training is scheduled, update the **RCM Set Up** field to **Onboarding**. If the client will not be using RCM, make sure the feature is opted out in the TO-record.

#### Adoption Calls {#adoption-calls}

The order of Adoption Calls is specifically designed to ensure that clients can pick up each additional piece and incorporate it easily into their existing knowledge about the Adit platform and their daily work flow. In each Adoption Call, you will configure that feature to meet the client’s needs as well as teach them how to use it. The client should pass any necessary information on to the rest of their staff as needed.

You should plan to make 1-2 Adoption Calls to each client per week; aim to have at least 3-4 days between each call. For example, if you have Adoption Call \#2 on Monday, you can reach out on Thursday or Friday for call \#3. As you complete each Adoption Call, check the corresponding box in the **Pending Adoption** section in the TO-record.

Adoption Call \#1: Online Scheduling (can be skipped if OS was covered in Core phase)  
Adoption Call \#2: Call Intelligence (if using CI)  
Adoption Call \#3: Patient Segments / Patient Lists and Mass Texting  
Adoption Call \#4: Email Campaigns and Drip Campaigns  
Adoption Call \#5: Treatment Plans (if using Practice Analytics)  
Adoption Call \#6: Internal Chat  
Adoption Call \#7: Follow Ups (if using Practice Analytics)

For more information on what to discuss in each Adoption Call, please see Adoption Conversations.

Once all required Adoption calls have been made, the following criteria must be met:

* PA Training \= Scheduled or Completed, or PA opted out  
* Pay Training \= Scheduled or Completed, or Pay opted out  
* The client’s adoption score has reached 100 (with Voice) or 70 (without).

For more information on adoption score metrics, please seeAdoption Metric Definitions.

At this point, the OB will need to evaluate the client’s status and if there are any ongoing issues. If the adoption score is met, the client is comfortable, and there are no issues with their platform or account, you will [make your final check-in call](#final-check-in-call) and move the client to **Pending Approval**.

If the client is still not comfortable with the platform, is escalated or upset, or has repeated or ongoing technical issues, they are not ready to move to CSM. Click the **Ongoing Issues** transition to move them to the Pending Resolution stage.

## Phase 3: Go Live {#phase-3:-go-live}

### Stage: Pending Resolution {#stage:-pending-resolution}

Resolution is a catch-all final stage for clients who have reached their adoption score but cannot move to CSM for some other reason. Common reasons include:

* The client is escalated.  
* They have continuing issues, i.e. ongoing call quality problems.  
* They have recurring issues, i.e. server app stops syncing every few days.  
* They have requested additional training or frequently ask very basic questions, indicating that they are not comfortable using the platform.  
* They have requested porting of additional numbers or purchased additional equipment that will need to be set up.

While clients are in Pending Resolution, the OB’s job is to check in with the client as frequently as they need in order to resolve their issues and/or de-escalate their account. This may include following up with the client directly and with internal teams to ensure issues are resolved thoroughly.

When all outstanding issues are resolved, you will have a final check-in call with the client.

#### Final Check-In Call {#final-check-in-call}

Once all issues (if any) have been resolved and the client has met their required adoption score, you will make a final check-in call to the client. During this call, you must:

* Inquire about how things are going with the platform.  
* Address any remaining questions, concerns, or issues.  
* Explain that you will be moving their account out of onboarding and over to our CSM team. Congrats on graduating\!  
* Inform the client that a member of our CSM team would like to speak to them regarding their onboarding journey and to ensure we have met their needs. Inform the client this call will take no longer than 15 mins and you would like to schedule it within the next day or two.

Once the check-in call is complete, the client is ready for CSM.  Update the **Check In Call Date** and **Notes For CS** fields in the TO-record. Make sure the correct contact person for the practice is updated on the TO-record, the Deal, and the Account in CRM, then click the **Ready for CSM** transition on the TO-record.

### Stage: Pending Approval {#stage:-pending-approval}

The approval stage is the last step in the onboarding process. It allows us a small measure of accountability to ensure that clients are set up for success at the end of their onboarding.

Approval is handled entirely by the Tech CSM team. They use the following criteria to determine if a client is ready to leave onboarding:

1. No open tickets.\*  
2. **Notes for CS** field is filled out with any and all helpful information the Tech CSM will need in order to call the client and have a positive, productive conversation.  
3. All training completed and configuration questions resolved.  
4. PA check complete and training scheduled (if applicable).  
5. Contacts updated in Deal and Account.  
6. Adoption score reached.   
7. Client does not have any questions/issues/hesitation about successfully using the Adit platform.  
   

***\*Note:** Minor bugs/tickets that aren’t hindering the client from utilizing the platform may still be open if the client is not escalated because of those outstanding issues. These tickets must be new (not ongoing issues), unique (not recurring issues), and isolated (not affecting any other parts of the platform) in order for the move to CSM to be approved.*

If a move to CSM is rejected, the TO-record will move back to **Pending Resolution**. The OB must work with the client to address any remaining tickets, questions, issues, escalations, etc. Once all issues are resolved, you can once again move the client to the approval stage by the **Ready for CSM** transition.

## Appendices {#appendices}

### Appendix A: CRM Fields {#appendix-a:-crm-fields}

It is solely the OB’s responsibility to ensure that CRM is updated and maintained at all times throughout the onboarding process. Within this document, there are specific indications of when to update certain fields or sections in CRM, primarily on the Tech OB record. If a field is not specified in this document, it does not excuse the OB from ensuring it is updated.

The TO-record is organized into sections that roughly correspond to the Stage of the TO-record. You can use that to help ensure that you are filling fields out at the right time. Below is a list of the sections of the TO-record; any sections with a name in **bold** contain at least one field that the OB must update manually.  Some fields in the TO-record will be updated by other teams; these are also indicated below.

* **Technology Onboarding Info**  
  * Updated by the OB.  
  * Technology Onboarding Owner and Technology Onboarding Name should only be edited by Managers.  
* **Sales Missteps**  
  * Updated by the OB if we discover something in onboarding that was either missed by the AE or misunderstood by the AE/Client.  
* Deal Details  
  * Automatically updates from Deal fields, do not edit.  
  * If any of these fields are incorrect, check and correct on the Deal.  
* **Module Opt In**  
  * Will sometimes be auto-filled depending on the client's package and other decisions made in the sales/signup process.  
  * OB should update manually as well when needed.  
* Account Set Up  
  * Filled in automatically when “Get Started” tasks are completed.  
  * If any of these fields are not filled in automatically:  
    * Let Manager know.  
    * Check the Adit App to see if the info is updated there.  
      * If so, update the fields manually.  
      * If not, get the info from the client and update it in the Adit App, then update the CRM fields.  
* Server Install  
  * Updated automatically if the app is self-installed by the client.  
  * Updated manually by the Server Install team if support assistance is needed.  
* Porting Status  
  * Updated manually by the Porting team  
* **Phone Install**  
  * First six fields in the left column are about their phone hardware shipment. These are updated by Asset Management if phones were ordered.  
  * Rest of the left column is updated by the OB.  
  * Right column used only if the phone install fails or there are issues; fields can be updated by the OB or by the VoIP technician. Please coordinate with the VoIP tech on a case-by-case basis.  
* **Pending Kickoff**  
  * All fields updated by the OB.  
* **Pending Config**  
  * Left column updated by the OB.  
  * Right column only used if the client is opting out of phones; updated by Manager.  
* **Pending Training**  
  * All fields updated by the OB.  
  * Left column is for Staff Training.  
  * Right column is for training scheduled with other teams (Practice Analytics and Pay).  
* Pending Adoption  
  * Left column All fields update automatically.  
  * Right column All fields updated by the OB.  
* **Pending Approval**  
  * Left column updated by the OB.  
  * Right column updated by the Tech CSM team.  
* Porting Details  
  * Filled in automatically when the client provides porting info in the Get Started process.  
  * Can be updated manually by the OB if needed.  
* **Whitelisting Details**  
  * Two fields the OB is required to update:  
    * Whitelisting Email  
    * Acknowledged by IT / Practice Manager  
  * All other fields are updated by the VoIP team if/when needed.  
* **RCM Set Up**  
  * Field updated by the OB.  
* **Call Intelligence Onboarding**  
  * All fields updated by the OB.  
* Practice Analytics Set Up  
  * Managed by the PA team.  
* Adit Pay Set Up  
  * Managed by the Pay team.  
* Key Data Points  
  * Updated automatically by fields and formulas.
