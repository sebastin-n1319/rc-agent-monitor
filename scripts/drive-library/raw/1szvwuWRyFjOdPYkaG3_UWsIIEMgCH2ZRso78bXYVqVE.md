Tech OB Whitelisting Ticket Handling Process

#### Day 1 \- The Tech OB is to send WL email to client / IT contact

* Desk \- use 6 Tech OB \- 02 Whitelisting Info template  
  * In table, add model \#, line & MAC address  
* Tech OB record update the following fields  
  * Whitelisting Ticket ID  
  * Whitelisting Email  
  * Acknowledged by IT / Practice Manager (when applicable)

#### Day 2 until Phone Install date

* Continue to follow up with the client / IT contact via call / email / sms to verify that WL has been completed successfully.  
* Once complete, update ticket with private comment and close ticket  
* In Tech OB record, update Acknowledged by IT / Practice Manager   
  *\*If not complete by PI date, continue below.*

#### Phone Install Day

* If WL is not completed by this date, OB is to explain the importance of completing WL to the client before completing the phone install call.   
  * Note: while WL is not always required, it is highly recommended to ensure the voice traffic is optimized on the practice’s network.  
  * Protects against Cyber attacks. VoIP phone systems are often targeted by fraud and denial-of-service attacks. Whitelisting helps prevent these attacks by only allowing approved IP addresses to communicate with protected resources.   
  * Improves IT security by having control over what can run on or access systems.   
  * Whitelisting rules or policies complement Network ACLs by explicitly defining which IP addresses are allowed to send and receive Voice traffic.  
  * Even if a Firewall / Router has not blocked any IP traffic or kept it open for reaching the Internet earlier, it is highly recommended to create these policies to group our Adit Voice traffic to be assigned the Highest priority for flowing in and out of the practice network seamlessly, even during low internet bandwidth   
  * Improved Performance: By limiting the number of allowed applications and devices, whitelisting can help improve network performance and reduce latency.   
  * Prioritizes Voice packets through techniques like QOS and bandwidth management which helps in improved call quality.  
* The OB is to explain to the client that our VoIP team will observe the call quality up until 1 week after porting is complete to ensure the practice does not face any issues with the service.   
* The OB will explain to the client if issues arise with the phone system, they need to contact Adit as soon as possible. 

#### After Install

* If the client faces issues after the phone install, WL **WILL BE** mandatory.  
* In the event the client does not have an IT person or can not complete the WL themselves, Adit can assist. The client will need to give Adit access to the practice’s network / firewall in order to complete the necessary steps.  
* The Tech OB needs to update the subject line of the WL ticket to the following:  
  * Whitelisting Needed \- Client Name and then assign to VoIP \- Whitelisting queue in Desk

#### 1 week after Poring has been completed

* At this point, if the client has not faced a single voip issue, then the WL ticket can be closed but first the following needs to be done:  
  * The Tech OB must email the client from the WL ticket using the following template:  
    * **Incomplete Whitelisting**  
  * Once the client acknowledges WL has not been completed, WL ticket can be officially closed
